# Animation/UI Library & Engine Research for a Lighthouse-100 Next.js 16 Portfolio

Date: 2026-11-04. Versions below are what npm/unpkg/bundlephobia served today unless noted.

## 0. Key constraints that shape every recommendation

- **Your stack is CSS Modules, not Tailwind.** Almost every "copy-paste" library below (Aceternity, Magic UI, Motion Primitives, Cult, Animata, HextaUI, Fancy, Kokonut, SmoothUI, Skiper, shadcn) ships Tailwind-class JSX. Only **React Bits** (CSS *and* Tailwind flavours), **Uiverse** (vanilla CSS option) and **Paper Shaders** (an npm package, style-agnostic) drop into a CSS Modules project without translation. Everything else is "read the source, port the idea".
- **Next.js 16** (released 2025-10-21) ships Turbopack by default, React 19.2+ canary features, and `<ViewTransition>` with zero config; `next lint` is gone; `images.qualities` defaults to `[75]`; `scroll-behavior: smooth` is no longer auto-injected (relevant to Lenis). Source: [Next.js 16 blog](https://nextjs.org/blog/next-16).
- **Lighthouse 13** (Oct 2025) changed audits to "insights" but **did not change performance scoring**, so the levers are still LCP/TBT/CLS/SI/FCP on a throttled mobile CPU. Source: [Chrome blog](https://developer.chrome.com/blog/lighthouse-13-0), [SEJ](https://www.searchenginejournal.com/google-lighthouse-13-launches-with-insight-based-audits/558051/).

## 2. Animation engines

### Motion (motion.dev) — `motion` **14.9.1**, MIT, React peer `^18 || ^19`
- Official sizes (Rollup, gz): `motion` component **43 kB** floor; `m` + `LazyMotion` **~5 kB** initial + `domAnimation` **+24 kB** / `domMax` **+38 kB**; `useAnimate` mini **3.3 kB**, hybrid **23 kB**; single hooks like `useReducedMotion` ~1 kB. Webpack/Turbopack shake slightly worse than Rollup. Source: [reduce bundle size](https://motion.dev/docs/react-reduce-bundle-size).
- v13/v14 (Sep–Oct 2026) were mostly internal cleanups with size wins (`scroll` −44%, `m` −20%, `useSpring` −30%) ([changelog](https://motion.dev/changelog)). React 19.3 works; use `motion/react` in client components, `motion/react-client` when you need RSC-friendly imports.
- Strengths: declarative enter/exit/layout, gesture props, `useScroll` for simple parallax. Weakness for agency-style work: no timeline-pinning/scrub primitive comparable to ScrollTrigger; split text is paid (Motion+) or DIY.

### GSAP — `gsap` **3.15.1**, Webflow "Standard (no charge) License"
- **Fully free for commercial use since 2025-04-30, including all formerly-Club plugins** (ScrollTrigger, ScrollSmoother, SplitText, MorphSVG, DrawSVG, Flip, Observer, etc.), shipped inside the normal `gsap` npm package. Only prohibited use: building a no-code visual animation tool competing with Webflow; no attribution required; not OSI open source (Webflow retains IP, can terminate on breach). Sources: [gsap.com standard license](https://gsap.com/community/standard-license/), [Webflow announcement](https://webflow.com/blog/gsap-becomes-free).
- Size: core entry **26.8 kB gz** (69 kB min) per [bundlephobia](https://bundlephobia.com/package/gsap). Plugins are separate ES modules (`gsap/ScrollTrigger`, `gsap/SplitText`) so you pay only for what you import; ScrollTrigger adds roughly 13–15 kB gz (community figures, unverified by GreenSock — core+ScrollTrigger ≈ 40 kB gz is the commonly quoted total). GSAP core cannot be tree-shaken internally.
- React: `@gsap/react` `useGSAP()` handles context/cleanup under Strict Mode and Fast Refresh. Latest releases: 3.14 (Dec 2025, MorphSVG smoothing), 3.15 (Apr 2026, adaptive directional easing, `easeReverse`) ([gsap release tags](https://www.gsap.com/blog/tags/release/)).
- **Lenis + GSAP pattern** (Lenis **1.3.27**, MIT, **5.3 kB gz** [bundlephobia](https://bundlephobia.com/package/lenis); README):
  ```js
  const lenis = new Lenis();
  lenis.on('scroll', ScrollTrigger.update);
  gsap.ticker.add((time) => lenis.raf(time * 1000));
  gsap.ticker.lagSmoothing(0);
  ```
  Use `lenis/react` (`<ReactLenis root>` + `useLenis`) in a client layout component; import `lenis/dist/lenis.css`. Notes: Safari caps 60 fps (30 in low-power); `syncTouch` is unstable on iOS < 16 — leave native touch scrolling on mobile. This exact pattern is what Trionn, San Rita and Arnaud Rocca's sites use (see §4).

### Native: CSS scroll-driven animations & View Transitions
- `animation-timeline: scroll()/view()`: Chrome/Edge 115+, **Safari 26+**, **Firefox 159+**, **88.25 % global** ([caniuse](https://caniuse.com/mdn-css_properties_animation-timeline)). Zero JS, runs off main thread — ideal for progress bars, parallax, reveal-on-view with `@supports (animation-timeline: view())` and a no-animation fallback. Not yet safe as the *only* mechanism for Safari ≤18 users.
- View Transitions (same-document): Chrome 111+, Safari 18+, Firefox 144+, **92.9 % global** ([caniuse](https://caniuse.com/view-transitions)). Cross-document: Chrome 126+, Safari 18.2+, Firefox not shipped ([Chrome docs](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document)).
- **Next.js 16 + React 19.3**: `import { ViewTransition } from 'react'` works in App Router with **no config**; route navigations are transitions, `<Link transitionTypes={['nav-forward']}>` drives directional slides, `name` pairs do shared-element morphs (thumbnail → project hero), `share="morph" default="none"` to customise. Add `::view-transition { pointer-events: none }` and a `prefers-reduced-motion` reset. Source: [Next.js view-transitions guide](https://nextjs.org/docs/app/guides/view-transitions) (updated 2026-10-15). This replaces GSAP/Barba-style page-transition plumbing for free.

### Verdict for scroll-choreographed agency-style sites
GSAP + ScrollTrigger + SplitText + Lenis is the industry pattern in every 2025–26 case study found, is now free, and costs ~45–50 kB gz total. Motion is the better fit for component-level UI state (hover/press/presence) and is what most copy-paste libraries assume. Running both is common (React Bits does) but costs ~70–90 kB gz; pick one as the "scroll/timeline" engine.

## 3. React Three Fiber / drei vs vanilla three

- `three` **0.187.0** MIT ([unpkg](https://unpkg.com/three/package.json)). Full WebGL ESM build ≈ **86 kB gz** (355 kB min); the WebGPU build is ≈171 kB gz; per three.js CI size reports ([PR 32154](https://github.com/mrdoob/three.js/pull/32154)). Tree-shaking helps little because shader chunks are always included — budget ~90–120 kB gz for any three scene.
- `@react-three/fiber` **9.8.2** MIT — peer `react >=19 <19.4`, `three >=0.156`; v9.8.0 added React 19.3 compatibility and synchronous root setup ([releases](https://github.com/pmndrs/react-three-fiber/releases), [unpkg](https://unpkg.com/@react-three/fiber/package.json)). **v10.0.0-alpha.6** (Oct 2026) is WebGPU-first with WebGL2 fallback, `@react-three/fiber/legacy` for GLSL, fixes `<ViewTransition>` stalls inside Canvas — not production yet.
- `@react-three/drei` **10.7.9** MIT — peer `react ^19`, `fiber ^9`, `three >=0.159` ([unpkg](https://unpkg.com/@react-three/drei/package.json)). `@react-three/postprocessing` 3.0.x pairs with three ≥0.182 ([pmndrs examples PR](https://github.com/pmndrs/examples/pull/95)).
- Next.js 16: Canvas must live in a `'use client'` component, loaded with `next/dynamic(..., { ssr: false })`; `transpilePackages: ['three']` is still the documented workaround for ESM examples imports ([R3F install docs](https://r3f.docs.pmnd.rs/getting-started/installation)). Mount **one persistent Canvas outside page content** (San Rita pattern) so route changes don't recreate the WebGL context.
- **Postprocessing on mobile**: bloom/DoF/SSAO are fill-rate bound; community guidance is DPR 1–1.5 on mobile vs 2 desktop, `multisampling={0}`, `mipmapBlur` with fewer `levels`, drei `useDetectGPU` to disable the EffectComposer on low tiers, and `<Canvas performance={{min:0.5}}>` adaptive DPR ([npm @react-three/postprocessing](https://npmjs.com/package/@react-three/postprocessing), [svilenkovic r3f notes](https://svilenkovic.com/3d/r3f-postprocessing)). For a Lighthouse-100 target, **skip full-screen post FX on mobile entirely**; do grain/dither/chromatic aberration inside the material shader instead.
- **R3F vs vanilla**: R3F costs ~+15–20 kB gz over three and adds a React reconciliation layer; Trionn chose vanilla three "for direct control over the shared render loop and resource management" and drives it from `gsap.ticker` ([Codrops](https://tympanus.net/codrops/2026/07/15/the-architecture-behind-trionn-coordinating-gsap-three-js-lenis-and-web-audio/)). Stefan Vitasović (R3F) and Arnaud Rocca/Thibault Guignand (**OGL**, a ~tens-of-kB alternative to three) show the other options. For "a few scenes" with shader planes/video textures, **OGL or vanilla three with one shared loop is leaner**; R3F pays off when you want drei helpers (Text, Html, Environment, ScrollControls) and declarative scene composition.

## 5. Recommended stack for this portfolio

**Engines (≈ 60 kB gz JS budget for motion, excluding three):**
1. **GSAP 3.15 + ScrollTrigger + SplitText + `@gsap/react`** — primary engine for text reveals, scroll pinning/scrubbing, marquees, magnetic buttons, image trails and preloader timelines. Free, battle-tested with Lenis, and every reference site uses it. Import plugins individually.
2. **Lenis 1.3.27** via `lenis/react`, wired to `gsap.ticker` exactly as in §2; desktop-only smoothing (`syncTouch: false`), keep native scroll on touch.
3. **React `<ViewTransition>` (Next 16 / React 19.3)** for page transitions and thumbnail→hero morphs instead of a JS transition library. 0 kB.
4. **CSS scroll-driven animations** behind `@supports` for cheap parallax/progress/reveals that need no JS; GSAP fallback only where needed.
5. **Skip Motion** unless you adopt Tailwind libraries wholesale; if you want its gesture/presence ergonomics for a few UI bits, use `LazyMotion` + `m` + `domAnimation` (~29 kB) rather than the 43 kB `motion` component.

**WebGL:**
- Keep **vanilla `three` 0.187** (already installed) with **one shared render loop driven by `gsap.ticker`**, one persistent canvas mounted in the root layout client component, `dynamic(..., { ssr: false })`, DPR clamped to 1.5 on mobile, and **no EffectComposer on mobile** (do grain/aberration in the fragment shader). Add R3F 9.8.2 + drei 10.7.9 only if you need drei helpers; wait for R3F v10 (WebGPU) to leave alpha.
- For hero/section backgrounds consider **`@paper-design/shaders-react` 0.0.82** (Apache-2.0, ~57 kB gz, no three) or, cheaper still, hand-written OGL/raw WebGL for a single shader plane — both avoid three's ~86 kB floor if the 3D scenes end up small.

**Components (CSS Modules friendly):**
- **React Bits** (CSS flavour) for ready-made SplitText/BlurText/ScrollVelocity/Magnet/ImageTrail/Dock/CircularGallery — audit that each pick uses gsap (not motion/three) to avoid dragging a second engine.
- **Motion Primitives** and **Fancy Components** as *reference implementations* to port (Text Scramble, Magnetic, Infinite Slider, variable-font hover) — MIT, small, readable.
- **Uiverse** for a pure-CSS preloader/loader if you want one.
- Avoid for this build: Aceternity (custom licence, SaaS look, three in several items), 21st.dev as a dependency (daily copy cap), Skiper (attribution clause), HextaUI (not an animation lib).

**Lighthouse-100 guardrails:** hero headline must be real DOM text (LCP), SplitText only after `document.fonts.ready` (CLS), defer Canvas init to `requestIdleCallback`/after first paint (TBT), `prefers-reduced-motion` kills Lenis + scrub timelines + view transitions, `images.qualities` tuned since Next 16 defaults to `[75]`, and test on real mid-range Android since Safari caps 60 fps and low-power mode 30 fps.
